### MMOLoader Example: Custom Triggers, Drop Items, Objectives

Source: https://gitlab.com/phoenix-dvpmt/mmocore/-/wikis/Plugin-API

This Java code demonstrates implementing a custom MMOLoader by overriding methods to load specific triggers, drop items, and objectives. It uses MMOLineConfig for parsing configuration and returns specific implementations or null if the key doesn't match. This allows MMOCore to recognize custom game logic elements.

```Java
@Override
    public Trigger loadTrigger(MMOLineConfig config) {
        if (config.getKey().equals("message"))
            return new MessageTrigger(config);
        if (config.getKey().equals("sound"))
            return new SoundTrigger(config);
        if (config.getKey().equals("command"))
            return new CommandTrigger(config);
        if (config.getKey().equals("item"))
            return new ItemTrigger(config);
        if (config.getKey().equals("exp"))
            return new ExperienceTrigger(config);
        return null;
    }
    @Override
    public DropItem loadDropItem(MMOLineConfig config, DropTableManager tables) {
        if (config.getKey().equals("droptable"))
            return new DropTableDropItem(tables, config);
        if (config.getKey().equals("vanilla"))
            return new VanillaDropItem(config);
        if (config.getKey().equals("note"))
            return new NoteDropItem(config);
        if (config.getKey().equals("gold"))
            return new GoldDropItem(config);
        return null;
    }
    @Override
    public Objective loadObjective(MMOLineConfig config, ConfigurationSection section) {
        if (config.getKey().equals("goto"))
            return new GoToObjective(section, config);
        if (config.getKey().equals("mine"))
            return new MineBlockObjective(section, config);
        if (config.getKey().equals("kill"))
            return new KillMobObjective(section, config);
        if (config.getKey().equals("getitem"))
            return new GetItemObjective(section, config);
        if (config.getKey().equals("clickon"))
            return new ClickonObjective(section, config);
        return null;
    }
    @Override
    public Condition loadCondition(MMOLineConfig config) {
        // TODO Auto-generated method stub
        return null;
    }
```

### Java: Load Objective by Config Key

Source: https://gitlab.com/phoenix-dvpmt/mmocore/-/wikis/Plugin-API/diff

This Java code snippet demonstrates a method for loading specific objective types (GoTo, MineBlock, KillMob) based on a configuration key. It utilizes MMOLineConfig and ConfigurationSection to instantiate the appropriate objective object, handling different objective types through conditional logic.

```java
@Override
public Objective loadObjective(MMOLineConfig config, ConfigurationSection section) {
  if (config.getKey().equals("goto"))
    return new GoToObjective(section, config);

  if (config.getKey().equals("mine"))
    return new MineBlockObjective(section, config);

  if (config.getKey().equals("kill"))
    return new KillMobObjective(section, config);
}
```

```APIDOC
Command: /rpg booster create <amount> [profession] [player]
  Description: Creates an EXP booster that applies to all online players.
  Parameters:
    - amount (integer): The percentage of extra EXP players will earn.
    - profession (string, optional): The specific profession the booster applies to. If omitted, it applies to all professions.
    - player (string, optional): The name of the player who created the booster. This is used for display purposes.
```

Details the configuration for the 'mineblock' experience source in MMOCore. This allows players to earn experience by mining specific block types, with options to control conditions like silk touch, crop growth, and player-placed blocks.

```APIDOC
mineblock Configuration:
  Allows players to earn experience by mining specific block types.

  Syntax:
  mineblock{type=BLOCK_MATERIAL;silk-touch=true;crop=false;player-placed=false}

  Parameters:
    type: The block material to mine. (e.g., BLOCK_MATERIAL)
    silk-touch: When enabled (true), no EXP is earned when using silk touch. Defaults to true.
    crop: When enabled (true), players don't get EXP unless crops are fully grown. Defaults to false.
    player-placed: When disabled (false), players don't get EXP from blocks placed by players. Defaults to false.

  Related Configurations:
    - The list of all crops can be found in the default Farming profession config file.
    - Supports MMOItems for configurable drop tables.
```

### MMOCore Drop Table Weight and Capacity Explained

Source: https://gitlab.com/phoenix-dvpmt/mmocore/-/wikis/Drop-Tables/diff

Explains the core mechanics of MMOCore drop tables, detailing how item weights interact with the capacity of a loot chest or system to determine how many items are dropped. It clarifies that the sum of selected item weights cannot exceed the specified capacity.

```markdown
Example scenario: you want ONLY one of these three items to drop and every item has 1/3 chance to be selected.

Every drop item has an item weight of 1, meaning that if this drop table is utilized by a loot chest (or any other system that supports MMOCore drop tables) with a **capacity** of 1, only one item will be selected.

When a drop table is used to generate random loot, the sum of all selected drop items WEIGHTS cannot exceed the CAPACITY specified. The same drop table can be used with different values for the capacity for practical reasons. If you use the drop table setup above with a capacity of 3, you can drop the three items at the same time. If you use it with a capacity of 2, 2 items will spawn at most.
```

### Disable MMOCore Classes, Skills, and Leveling

Source: https://gitlab.com/phoenix-dvpmt/mmocore/-/wikis/Player-Classes/diff

This procedure outlines how to disable the player class, skill progression, and leveling systems within MMOCore. By emptying the designated class folder, MMOCore will revert to a default state where players have no active class, effectively disabling these features and allowing the system to be used purely for its profession mechanics.

```APIDOC
Feature: Disable Classes, Skills, and Leveling

Purpose:
To disable the player class, skill, and leveling systems in MMOCore, allowing its use solely for the profession system.

Method:
1. Locate and navigate to the MMOCore configuration directory.
2. Find the `/class` folder within the configuration directory.
3. Completely empty the contents of the `/class` folder. **Important:** Do not delete the `/class` folder itself, as it may be regenerated.

Effect:
- MMOCore will use an empty, default class for all players.
- Player leveling will be disabled as the default class has no leveling rewards.
- Skills will be disabled as they are bound to specific classes.
- The system can still be utilized for its profession system features.
```
